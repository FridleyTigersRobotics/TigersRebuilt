  1) Quick sanity checks (first power‑on)

CANcoder zeros: With wheels pointing robot‑forward, verify each module’s reported angle looks reasonable (0–2π). If you saved zero in the device, offsets in code stay 0_rad.
Module directions: Command a tiny forward x‑speed; all wheels should point forward and roll forward. If a wheel drives backward, swap that module’s drive inversion in config or flip its kP sign only if using a device loop.
Azimuth response: Slowly command rotation; each module should steer smoothly to the set angle without hunting. If it oscillates, lower turn kP (e.g., from 0.5 → 0.35).


2) Drive closed‑loop (RIO PID+FF) quick tune
You’re using PID + feedforward to volts with m/s feedback:


Set FF first

Leave drive kP = 0.2, kD = 0.
Ramp to a few steady speeds (e.g., 0.5, 1.5, 3.0, 4.0 m/s).
Adjust kV so the PID contribution at steady state is small (near 0 V).
If the wheel sticks at very low speed, add a small kS (e.g., 0.2 V).



Tighten regulation

Increase kP until you get good tracking without oscillation (typical 0.15–0.35).
Add a little kD only if you see overshoot on step changes (often not needed).
